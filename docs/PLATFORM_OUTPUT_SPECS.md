# 平台输出规格适配设计（PLATFORM_OUTPUT_SPECS）

> 关联：ARCHITECTURE_ANALYSIS.md（模块依赖）、VALUE_PROPOSITION.md（价值主张）
> 决策背景：用户评审指出——不同短视频平台对视频尺寸/比例要求不同，出片时应**强制选择目标平台**，并据此生产对应规格，而非统一输出固定尺寸。

---

## 一、现状与问题

当前出片引擎（`gpt_sovits/make_scroll_video.py`）**尺寸写死**：

```
make_scroll_video.py:121   W, H = 1080, 1920        # 固定竖屏 9:16
make_scroll_video.py:130  MAX_W = W - 120           # 依赖 W
make_scroll_video.py:175  CURRENT_Y = 880            # 依赖 H（中上部锚点）
make_scroll_video.py:126  PANEL_TOP = 560 / PANEL_BOTTOM = 1560  # 依赖 H
```

所有字幕布局常量（面板、字号锚点、行距、左右边距）都基于 `1080×1920` 推导，
**出片分支（`python-pipeline/server.py` 的 `/generate`）不接收 platform 参数**，出片页也无"目标平台"选择项。
结果：无论发到视频号、抖音还是小红书，都一律出 1080×1920，小红书场景下上下被压、留白不合规。

**结论：用户意见正确，当前缺失"按平台规格出片"能力，且未强制平台选择。**

---

## 二、各平台真实规格对照（2026 现行）

| 平台 | 主推比例 | 推荐分辨率 | 说明 | 与现状差异 |
|---|---|---|---|---|
| 视频号 | 竖屏 9:16 | **1080×1920** | 横屏也支持 16:9 | 现状已满足 |
| 抖音 | 竖屏 9:16 | **1080×1920** | 横屏也支持 16:9 | 现状已满足 |
| 小红书 | 竖屏 **3:4** | **1080×1440** | 3:4 有流量倾斜；也兼容 9:16 | **现状不满足**（出 1920 会被压缩/留黑边） |
| 快手 | 竖屏 9:16 | **1080×1920** | 与抖音/视频号同规格；快手开放平台需企业认证 | 现状已满足（已纳入全集） |

**关键差异点**：小红书偏 3:4（1080×1440），与视频号/抖音的 9:16（1080×1920）**高度不同（1440 vs 1920）**。
这正是"平台规则不同 → 必须强制选平台并适配尺寸"的真实依据。

> 注：平台注册表已统一为全集 6 家（视频号/抖音/小红书/快手/B站/YouTube）。其中**选题维度子集 = 视频号/抖音/小红书/快手**（4 家短视频，调性适配有意义）；B站/YouTube 为横屏长视频托管，不纳入选题调性维度，仅作发布目标。规格表照列全集。

## 三、技术约束（必须诚实交代）

### 3.1 scroll 滚动字幕卡模式（PIL 自绘）—— 完全可控，可干净多尺寸
- 画布、字幕、标题全部由 PIL 逐帧绘制，**不依赖任何外部视频素材**。
- 所有布局常量均能从 `(W, H)` 按比例派生（与 P4 字幕参数化思路一致）：
  - `ratio = H / 1920`，`CURRENT_Y = int(880 * ratio)`，`PANEL_TOP/BOTTOM` 同理按比例
  - `MAX_W = W - 120`（已用 W 表达）、`LEFT_X=80` 等左右边距与 W 无关可保留
- **改造量小**：把模块级常量收进 `build_layout(W, H)` 函数，出片时按平台规格初始化即可。当天可落地。

### 3.2 avatar 数字人模式（HEYGEM face2face）—— 受源素材约束
- HEYGEM 是单人脸嘴型对齐，输出尺寸**跟随输入静音模特视频**的尺寸。
- 当前静音模特（BGZSP20260721_t18_silent.mp4 等）均为 **1080×1920 竖屏**，故 avatar 出片天然是 9:16。
- **要支持小红书 3:4，两条路**：
  - 理想方案：准备 1080×1440 的静音模特素材（需重录/裁剪），HEYGEM 直接出 3:4；
  - 折中方案：先统一出 1080×1920，出片后对成品做 **center-crop → 1080×1440**（字幕在中上部，crop 后仍在安全区，可接受）。
- **结论**：avatar 模式一期先强制"竖屏平台"（视频号/抖音通用 9:16），小红书 3:4 留二期（center-crop 快速上线，或补 3:4 模特做理想方案）。

## 四、落地方案

### 4.1 出片页"目标平台"强制选择（核心）
- 出片页（scroll.blade.php）新增**必填**下拉：「目标平台」= 视频号 / 抖音 / 小红书 / 快手。
- 未选平台则禁止提交（前端 disabled 提交按钮 + 后端校验 `platform in {视频号,抖音,小红书,快手}`）。
- 平台选择决定 `PLATFORM_SPECS[platform] = (W, H)`：
  ```
  视频号 → (1080, 1920)
  抖音   → (1080, 1920)
  小红书 → (1080, 1440)
  快手   → (1080, 1920)
  ```

### 4.2 server.py /generate 透传 platform → 出片尺寸
- `/generate` 分支新增 `platform` 参数，映射为 `(W, H)` 传给 `make_scroll_video.main(mode="scroll", width=W, height=H, ...)`。
- avatar 模式：platform 仅用于记录发布规格 + 二期 center-crop 依据；一期统一 1080×1920。

### 4.3 打通 P5 选题 → 出片（避免重复选择）
- P5 选题已选平台（视频号/抖音/小红书/快手，取选题子集），出片页加载时**自动带入该平台预填**，用户可改不必重选。
- 这样"强制选平台"在选题环节发生一次，出片环节继承+可改，体验不分裂。

### 4.4 质检增强：分辨率校验
- `ai_qc_video` 已读取视频 `width/height`，新增规则：校验实际分辨率是否匹配所选平台规格，
  不匹配则告警（如"所选小红书但出片为 1920，建议重选或裁剪"），把"实用"落到实处。

## 六、设计原则（回应"科学性"）

- **规格即数据**：平台规格集中为 `PLATFORM_SPECS` 字典（与 AUTO_PUBLISH_DESIGN 的 `PLATFORMS` 注册表共用同一份事实源），新增平台只改一处。
- **强制前置**：平台选择作为出片前置条件（与"克隆前置"同构），不符合规格的视频在源头被拦截，而非发布时才发现。
- **不破原有默认**：未传 platform 时仍按 1080×1920 渲染（向后兼容，已生成的任务不受影响）。
